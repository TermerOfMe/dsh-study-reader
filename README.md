# 研读 · Study Reader

在 DSH 主页面按原版式阅读 PDF、Word 和 PowerPoint，并把阅读变成可检索、可追问的学习过程。

本版本只保留 **原貌阅读**：不再提供文字重排的“研读视图”。PDF 由 Host 的 PDFium 渲染页面图、PDF.js 提供文字层；Word / PowerPoint 先经 DSH 自带的 Office 转 PDF 服务转换，再按原貌显示。

- **原貌阅读**：保留原版式、图表、公式和分页，可直接在页面上框选文字。
- **单页 / 连续页**：单页一次显示一页；连续页上下滚动，自动加载视口附近以及当前页前后各 2 页，离开这个窗口才释放画布。
- **全文查找**：右上角放大镜搜索目录标题和提取出的正文段落，结果带页码与上下文，回车/方向键切换，点击直接跳到对应页。
- **诊断信息**：右上角 `i` 按钮查看插件版本、页面渲染引擎、模型/Office 可用性和当前文档统计，可一键复制用于反馈问题。
- **注入的上下文**：每条问答回答和每条译文下方都有 **查看注入的上下文**。展开后可以看到这次请求实际发送的系统提示、用户消息（文档上下文、历史对话和问题）、按顺序附上的图片缩略图，以及阅读位置、图片/字符/估算 token 数、是否裁剪、是否注入全书概览、模型加读的页面、状态、耗时和 token 用量；可以分别复制系统提示与用户消息。
- **思考过程**：模型返回推理内容时，回答和译文上方会出现 **思考过程**，流式显示推理文本；生成期间默认折叠，只显示“正在思考…”和字数，点击才展开，生成结束后可随时折叠或复制。
- **框选操作**：选中正文后出现浮动工具栏，可翻译、追问或直接解释。
- **区域引用**：正常拖动仍然是选文字；**按住 Ctrl（Mac 为 ⌘）拖动** 则是在页面上框选一个区域。这个区域会像选中文字一样成为引用，并在提问或翻译时把框选截图作为图片一起发给模型。普通文字选择也会附带所选区域的截图。
- **上下文翻译**：不只是翻译选中的句子，还会参考所在段落、前后文和小节标题；默认英译简中，可切换目标语言。
- **侧边问答**：两种模式——
  - **学习模式**：只依据当前位置及之前的内容回答；如果文档后面不远就有更系统的解释，会先提醒“继续读”，并可一键跳到对应页。
  - **重读模式**：可以使用全文，主动联系不同章节、概念、例子和例外。
- **页面图片上下文**：问答时会把当前 PDF 页面作为图片一起发给支持图片的模型；模型还可以主动再要最多几页（学习模式只能要当前页之前的页），因此中文文字层缺失的 PDF 也能被读懂。
- **全书概览**：目录面板的 **概览** 按钮会分批读取每章首页，生成“每章讲什么”的章节摘要并缓存；之后重读模式的问答会自动带上这份概览。

所有解析、翻译与问答都在本机 Host 侧完成；问答和译文不会写入 DSH 的 Session 记录。

## 使用

1. 刷新 DSH 页面。
2. 点击左侧导航栏的 **研读** 图标。
3. 点击 **打开文档**，选择工作目录、主目录或直接输入文件路径。
4. 在页面上拖选文字：
   - **翻译**：译文出现在右侧“翻译”页，可随时更换目标语言。
   - **追问**：把选中段落带进右侧问答框，继续输入问题。
   - **解释**：直接让助教解释这段内容。
   - 如果页面文字选不出来，按住 **Ctrl（Mac 为 ⌘）** 在页面上拖动出一个矩形，效果和选中文字一样；提问/翻译会使用该区域的截图。
5. 在问答顶部切换 **学习模式 / 重读模式**。
6. 顶部 **目录** 优先使用 PDF 自带的书签（标题、层级和页码都来自文件），没有书签的 PDF 才回退到按字号识别的标题；可跳到对应页。目录默认只列出章标题，点章节左侧的箭头才展开该章的小节，再点标题跳转。目录右上角的 **概览** 会分批阅读每章首页，生成“每章讲什么”的章节摘要并缓存。原貌默认单页，可在页码左侧切换为 **连续页**：页面上下排列，滚动时自动加载视口附近和当前页前后各 2 页，不必反复点“下一页”。两种方式都支持框选；页码框和上一页/下一页在连续页中会滚动到对应位置。
7. 右上角 **查找** 可搜索目录标题与正文段落；**诊断** 面板可查看版本、渲染引擎和最近问题，反馈时直接复制。目录仍在后台提取时，右上角目录按钮会先显示为禁用态，完成后自动启用。每条回答/译文下方的 **查看注入的上下文** 可以展开本次发送的完整提示词、图片和统计；模型返回推理时，上方的 **思考过程** 会显示推理内容。
8. 右上角的返回箭头用于回到对话。如果从插件切回对话时出现白屏，请先强制刷新页面；仍复现则重启 DSH，并把浏览器 Console 的报错反馈给插件作者。

阅读进度、当前文档、问答记录和翻译记录保存在浏览器本地（`localStorage`），按文档路径区分。最近打开的文件可以在欢迎页或打开对话框中找到。

## 文件类型

| 类型 | 原貌视图 |
|---|---|
| `.pdf` | PDF.js 渲染，可单页或连续页查看，可框选文字 |
| `.docx` | 经 Office 转 PDF 后用 PDF.js 查看，可框选 |
| `.pptx` | 经 Office 转 PDF 后用 PDF.js 查看，可框选 |
| `.doc` / `.ppt` | 经 Office 转 PDF 后用 PDF.js 查看，可框选（需要 Office 服务） |

Markdown 和纯文本没有原貌页面，本版本不再支持打开。没有 Office 转 PDF 服务时，`.docx` / `.pptx` 无法显示原貌，会提示改用可转换的文档。扫描版 PDF 没有文本层，原貌可以看到页面，但无法框选文字（本插件不做 OCR）。

## 配置

配置写在 profile 的 `cordis.patch.yml` 中本插件的行上；未写的字段使用默认值。改配置后需要重载 Host。

```yaml
- id: study-reader
  name: '@local/dsh-study-reader'
  config:
    defaultTargetLanguage: zh-CN
    maxDocumentBytes: 0
    maxPdfPages: 500
    maxPdfChars: 2000000
    learningContextChars: 24000
    lookaheadChars: 6000
    rereadContextChars: 48000
    translationContextChars: 6000
    maxAnswerTokens: 4096
    maxTranslationTokens: 1200
    temperature: 0.3
    cacheDocuments: 8
    visionPages: true
    visionMaxPages: 4
```

| 字段 | 默认 | 含义 |
|---|---|---|
| `defaultTargetLanguage` | `zh-CN` | 翻译目标语言的初始值 |
| `maxDocumentBytes` | 64 MiB（代码默认） | 单个源文件大小上限；`0` 表示不限制（见下方说明） |
| `maxPdfPages` | 500 | PDF 最多解析页数 |
| `maxPdfChars` | 2,000,000 | PDF 最多提取字符数 |
| `learningContextChars` | 24,000 | 学习模式保留的“已读内容”字符上限 |
| `lookaheadChars` | 6,000 | 学习模式用于判断“后面是否马上解释”的后文窗口 |
| `rereadContextChars` | 48,000 | 重读模式可用的全文/检索上下文上限 |
| `translationContextChars` | 6,000 | 翻译时提供的前后文字符上限 |
| `maxAnswerTokens` | 4,096 | 单次问答的输出上限（推理占用的 token 也计入；为空时会自动用 2 倍预算重试一次） |
| `maxTranslationTokens` | 1,200 | 单次翻译的输出上限 |
| `temperature` | 0.3 | 生成温度 |
| `cacheDocuments` | 8 | Host 内存中保留的已解析文档数 |
| `visionPages` | `true` | 问答时是否把 PDF 页面图片发给模型（仅 PDF，且模型需支持图片） |
| `visionMaxPages` | 4 | 模型每次最多可额外请求的页面数 |

`maxDocumentBytes` 的代码默认是 64 MiB，用来避免误打开超大文件时 Host 和浏览器同时占用过多内存。设为 `0` 即取消这个插件级限制；本插件的 `cordis.patch.yml` 和本机 profile 都已设为 `0`。PDF 的原貌预览会走 Range，不再把整份文件读进浏览器；但文字提取和 Office 转换仍会在 Host 读入文件，100 MB 以上的文档首次准备可能较慢。

问答和翻译使用 DSH 当前的默认模型（“模型设置”中的默认选择）。没有默认模型时，阅读仍然可用，但问答和翻译会显示不可用提示。

## 实现

- Host：`index.js` + `lib/`。`lib/extract.js` 用 `pdfjs-dist` 提取 PDF 文字；用内置的轻量 ZIP + OOXML 解析器读取 DOCX/PPTX，不依赖 Office 编辑器。提取出的块和页用于框选映射、目录跳转和问答上下文。PDF 目录优先读取文件内嵌的 outline（书签），把每个目标页解析成 1-based 页码，再映射到最终页列表；只有没有 outline 的 PDF 才按字号把大字号行识别成标题。`lib/context.js` 负责两种模式的上下文裁剪和“后文即将解释”的标记。`lib/llm.js` 通过 Host 的 `llm` 服务直接调用默认模型，不创建 Session。
- Client：`client.js`。在主页面 `main` 槽注册面板，在 `sidebar.panellist` 槽注册入口；所有请求走同源 `/api/dsh-study/*` 路由，流式回答使用 NDJSON。目录面板把扁平目录整理成“章 + 子项”：默认只渲染一级标题，章左侧的箭头控制该章子项是否挂载；没有一级标题的文档（例如 PPT）保持平铺，不会把第一张幻灯片当成章把所有内容收起来。
- 原貌翻页：PDF 页面由 Host 的 PDFium（WASM）按页渲染并编码成 JPEG 页面图，浏览器把页面图放进 canvas；PDF.js 只负责页码、全文和透明文字层。单页模式一次显示一页，连续页模式用 `IntersectionObserver` 加载视口附近页面，并保留当前页前后各 2 页。目录和“继续阅读”会按块所在页定位到 PDF 页码。
- 性能：不再让 PDF.js 在浏览器里解码 7201×4281 级别的扫描图。PDFium 单页首次渲染并编码约 0.7 s（第 50 页），同一页再次请求命中 Host 缓存约 14 ms；PDF.js 通过 `/preview` 的 Range 路由按需读取，不再把整份 PDF 下载并复制到渲染进程。连续页渲染 **视口 ±600px 与当前页前后各 2 页的并集**：当前页立即开始，前后各 1 页在 120ms 后开始，再远一页仍延迟 600ms；只有离开这个窗口的页才释放画布，所以往回翻一页会直接复用已经画好的 canvas 和透明文字层，不再重新拉图、重建。阅读区始终预留滚动条宽度，避免滚动条出现/消失把页面宽度改来改去、触发整页重渲染。PDF 的当前页预热只预取文字层，不预取 PDF.js 的 operator list，避免扫描页再次在 Worker 里解码大图。
- 懒提取：PDF 的 `/open` 只返回轻量文档（`extraction: "pending"`），原貌先用 PDFium 页面图显示；客户端随后调用 `/extract` 在后台提取文字，完成后补齐 `pages/blocks/toc`。目录和问答等提取完成后可用；如果提取尚未完成就提问或翻译，Host 会先等待这一次提取。
- 安全：POST 路由要求自定义请求头并校验同源 `Origin` / `Sec-Fetch-Site`；文件只在 Host 本机读取。预览与阅读路由不开启 CORS。
- 页面图片问答：`ask` 在回答前先把当前页渲染成 JPEG（复用页面图缓存），通过 `attachments.saveImage` 变成 durable `ImageBlock` 引用；再用一次小预算调用请模型返回 `{"pages":[…]}`，按模式限制页码后把额外页面图一起附上。学习模式只允许当前页及之前，重读模式允许任意页。图片只在模型声明支持 `image` 输入时启用。
- 框选引用：文字选择会把所选矩形换算成页面内的 0–1 归一化坐标，和页号一起发给 Host；区域引用由 `useRegionSelection` 监听滚动容器，只有按住 Ctrl/⌘ 的拖动才进入截图模式，得到同样的坐标。Host 用 PDFium 把该页按 1600px 重新渲染，按坐标裁切并留一点边距，必要时放大到至少 320px，再保存为 `ImageBlock`。问答时它排在图片列表第一位，系统提示会说明“第一张图是用户引用的原文”；翻译允许文字为空、只靠这张图。
- 上下文查看与思考过程：`lib/context-log.js` 在每次问答/翻译调用前记录最终的 system、用户消息、图片描述和统计，只放在 Host 内存里（每个文档最近 12 条、最多 8 个文档），不写 Session 也不落盘；回答消息只带一个 `contextId`，展开时通过 `/context` 取文本、通过 `/context-image` 按同一套 PDFium 渲染/裁切参数重算图片。`lib/llm.js` 把模型的 `reasoning-delta` 流式转成 NDJSON 的 `reasoning` 帧，客户端合并进回答并同步记录到上下文条目。
- 全书概览：`bookMap` 始终把“章 + 前 6 个小节 + 页码”压缩进上下文；目录的 **概览** 会分批（受附件的 `maxImagesPerMessage` 限制）把每章首页发给模型，流式生成并缓存逐章摘要。缓存的摘要只注入重读模式，避免学习模式提前知道后文。
- 输出预算：`maxAnswerTokens` 默认 4,096；如果推理模型在产生任何正文前就用完预算，`llm.js` 会用 2 倍预算（上限 16,384）重试一次，并提示模型压缩推理。
- 查找与诊断：`searchBlocks` 同时搜索 outline 标题和提取出的正文块，大小写不敏感，最多返回 200 条并带页码与上下文；诊断面板只读 `/bootstrap`、当前文档状态和正在使用的渲染引擎，不额外请求 Host。表格、目录、文件浏览器、查找和诊断共用 `useModalFocus`：焦点限制在面板内，Esc 关闭并把焦点还给触发按钮。
- 版本：`package.json` 是唯一版本来源，`lib/app.js` 读取后通过 `/bootstrap` 下发给浏览器；回退警告和诊断面板都使用这个值。`npm run check` 校验 manifest、lockfile、包内文件清单以及代码里不再出现手写版本号。
- 主题：控件使用 DSH 的 `--dsw-alias-*` 变量；品牌色按钮的前景使用 `--dsw-alias-label-primary-foreground`，随浅色/深色主题自动反转。表单控件的 `font:inherit;color:inherit` 重置使用零特异性的 `:where()`，不会覆盖按钮自己的颜色。PDF 纸张固定白底，因此页面内的加载/错误文字、忙碌提示和框选高亮使用固定的纸面配色；原生下拉选项跟随 `color-scheme`。

`pdfjs-dist`（Apache-2.0）、`@hyzyla/pdfium`（MIT wrapper，PDFium BSD-3-Clause）和 `@napi-rs/canvas`（MIT）作为运行时依赖随插件安装。其余文档解析代码在本仓库内。

## 已知限制

- 只提供原貌阅读，不提供文字重排视图；复杂 PDF 的阅读体验以原版式为准。
- PDF 打开后目录和问答上下文需要等后台文字提取完成（标题下会显示“正在建立目录与问答上下文…”）；扫描版或无法提取文字的 PDF 仍可看原貌，框选不可用，但问答可以使用页面图片（模型支持图片时）。
- PDF 目录最多保留 3 层、300 条；没有书签的 PDF 只能按字号启发式识别标题，公式、图表标题和试卷密封线附近的大字可能被误判或漏掉，扫描版 PDF 没有文字层时也不会生成目录。
- 页面图片问答只在默认模型声明支持 `image` 输入时启用，否则自动退回纯文字；每问会额外消耗 1–5 张页面图的 token，概览会分批上传每章首页并调用模型，首次生成可能需要几十秒，缓存只保存在 Host 内存中（重启后失效）。
- 区域引用和文字选区截图同样依赖图片模型；框选区域很小时会被放大到至少 320px，清晰度受页面渲染宽度限制；只靠截图翻译时，识别效果取决于模型的读图能力。
- 上下文记录只保存在 Host 内存：DSH 重启、文档被缓存淘汰，或同一文档又问了 12 次之后，旧回答的“查看注入的上下文”会提示记录已失效；图片是按需重新渲染的，首次展开会略慢。全书概览会分批调用模型，它把所有批次的输入合并到同一条记录里，用“第 N / M 批”分隔。
- 思考过程只有在模型/接口实际返回 `reasoning-delta` 时才有；不返回推理的模型只显示答案。推理文本也会占用回答的输出预算，`maxAnswerTokens` 仍然适用。
- Word 没有固定分页信息，Office 转 PDF 后的页码与 Word 的“节”、PPT 的“张”不总是一一对应；框选问答和目录跳转按包含关系/比例映射，极端情况下上下文段落可能不够精确。
- 连续页会保留当前页前后各 2 页的画布（通常 5 页左右，加上视口附近最多约 6–7 页）。Host 的 PDFium 页面图按 CSS 宽度的 2× 渲染：800px 栏宽时单页 canvas 约 1600×2266（约 14.5 MB），1200px 栏宽时约 2400×3394（约 32 MB），保留 5 页就是 70–160 MB 的 GPU/画布内存。翻到这个窗口以外的页仍会重新渲染。连续页会为每一页保留一个占位块，页数很多时切换瞬间会有一次排版开销。PDF 页面图编码为约 0.2–1.2 MB 的 JPEG；Host 只缓存最近几页，首次访问未缓存的页仍需约 0.15–0.6 s。
- 连续页会为视口附近和当前页前后各 2 页建立 PDF.js 文字层：当前页优先，前后各 1 页在 120ms 后跟进，文字极密集的页面仍可能带来短暂主线程开销。
- PDF 首次打开不再把整份文件读入浏览器：PDF.js 用 Range 只取 xref、页面字典和文字流，Host 的 `/preview` 直接按字节范围读磁盘；Office 仍需先转成 PDF。超大 PDF 的首屏仍受 Host 文字提取和 PDFium 首次打开影响。
- 超长文档的上下文会按预算裁剪/检索，可能遗漏远处细节；可缩小问题范围或结合目录重问。
- 查找只覆盖“能提取出来的文字层”和 PDF 目录标题。本机的 Easy-RL 教材就是一个反例：它不是扫描件，中文用的是 FandolSong 的 CID 字形编码（Identity-H），内嵌字体没有 ToUnicode 映射；页面能把字形正常画出来，但提取器拿到的只是字形编号、对不上汉字，所以提取结果几乎只有西文和公式。查中文只能命中目录标题，命中不了正文句子。这不是搜索逻辑的问题，也不是没有文本层，而是这份 PDF 缺少“字形编号 → Unicode”的对照表。问答已经改为附带页面图片来绕过这一点；搜索和框选仍然受文字层限制。
- 加密 PDF 目前只给出明确提示，需要用系统 PDF 阅读器打开，还没有在插件内输入密码的流程。
- 不提供编辑、批注导出或跨设备同步；问答/翻译记录保存在当前浏览器。
- Markdown 和纯文本没有原貌页面，本版本不再支持打开。
